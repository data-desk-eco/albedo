# Albedo

Template-driven vessel activity viewer. Fully static, client-side architecture.

## Quick Start

```bash
make install   # Install dependencies (yarn + uv)
make dev       # Dev server at localhost:5173
```

## Project Structure

```
albedo/
├── src/                    # Frontend application (vanilla JS + MapLibre GL)
│   ├── main.js            # App initialization, UI handlers, map lifecycle
│   ├── cog.js             # COG tile rendering with year-based colorization
│   ├── config.js          # MapLibre style generation, manifest-driven config
│   ├── data.js            # Data layer init (PMTiles protocol, vessel queries)
│   ├── vessel-tiles.js    # Hilbert-indexed binary vessel data for tooltips
│   ├── geo.js             # Coordinate conversions (Mercator, grid snapping)
│   ├── i18n.js            # Multi-language support with localStorage persistence
│   └── style.css          # Dark theme, responsive layout
├── scripts/               # Data pipeline scripts
│   ├── fetch_*.sh         # GFW API data fetching
│   ├── convert.sh         # JSON to Parquet conversion
│   ├── export_raster.sh   # COG generation (uses create_raster.py, raster_utils.py)
│   ├── export_pmtiles.sh  # Vector tile generation via tippecanoe
│   ├── export_tiles.py    # Hilbert-indexed binary vessel data
│   └── export_manifest.js # Manifest generation from template
├── etl/
│   └── transform.sql      # DuckDB SQL transformations
├── tools/
│   ├── cog-tiles/         # Reusable COG tile renderer library (npm package)
│   └── gfw2cog/           # Alternative Rust CLI for fetching/converting data
├── data/                  # Data files (gitignored, generated by pipeline)
├── .env.example           # Configuration template
├── manifest.template.json # Runtime config template with ${VAR} substitution
├── Makefile               # Build orchestration
└── vite.config.js         # Dev server with range request support
```

## Data Pipeline

```bash
make fetch     # GFW API → data/gfw/*.json (monthly files)
make convert   # JSON → Parquet (compressed columnar format)
make transform # SQL → data/data.duckdb (vessel positions, activity, protected areas)
make tiles     # Export COG heatmaps (aggregate + per-vessel-type)
make export    # PMTiles + manifest + vessel binary data
```

## Architecture

The app is fully static - all computation happens in the browser:

```
GCS/CDN                          Browser
├── vessel_heatmap.tif (COG)     geotiff.js → raster tiles via cog-tiles
├── vectors.pmtiles              pmtiles → vector layers (protected areas)
├── vessel_data.bin              vessel-tiles.js → Hilbert-indexed tooltips
├── manifest.json                config + layer definitions
└── index.html + JS              MapLibre GL → composite rendering
```

## Configuration

Copy `.env.example` to `.env` and configure:

- **Region bounds**: `SOUTH_LAT`, `NORTH_LAT`, `WEST_LON`, `EAST_LON`
- **Map view**: `CENTER_LON`, `CENTER_LAT`, `INITIAL_ZOOM`
- **Data source**: `GFW_API_TOKEN`, `YEARS`, `VESSEL_TYPES`
- **UI**: `UI_TITLE`, `DEFAULT_LANG`, `PLACES_JSON`

Manifest is generated from `manifest.template.json` via `scripts/export_manifest.js`.

## Key Dependencies

- **Frontend**: maplibre-gl, geotiff, pmtiles
- **Pipeline**: duckdb (SQL engine), rasterio (COG creation), tippecanoe (PMTiles)
- **Dev**: vite (bundler with custom range request middleware)

## Alternative Tools

The `tools/gfw2cog` Rust CLI provides an alternative data pipeline that can:
- Fetch data directly from GFW API with caching
- Convert JSON files to COG in parallel
- Handle antimeridian crossing automatically

Build with `cargo build --release` and run `gfw2cog --help` for usage.
